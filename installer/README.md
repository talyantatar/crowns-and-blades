# Crowns & Blades installer

`CK3xBL-Setup-<version>.exe` is the player download. It is one file that installs:

- the Crowns & Blades app, which is self-contained, so players need no .NET install;
- the CK3 mod;
- the Bannerlord module.

It is written in C# for **.NET Framework 4.8**, which comes with Windows 10 and 11, so the setup itself also needs
nothing extra. It installs per user, without administrator rights. It asks for administrator rights only when
Bannerlord's `Modules` folder cannot be written otherwise.

```
installer/
  src/                 CK3xBL-Setup.exe (WinForms wizard, silent mode, uninstaller, elevated helper)
  tests/               CK3xBL.Setup.Tests.exe: the headless self-test, plus "pack" (builds the release setup) and "icon"
  assets/              app.manifest, CK3xBL.ico (generated by "icon" from the same design as the tray icon)
  PAYLOAD_LAYOUT.md    what the release script stages, the manifest, the exe format, the pack command
```

## Build and test

```powershell
dotnet build installer/tests/CK3xBL.Setup.Tests.csproj -c Release   # builds src too (net48, offline)
installer/tests/bin/Release/net48/CK3xBL.Setup.Tests.exe selftest   # about 20 s; prints PASS/FAIL per test
```

- Nothing beyond the SDK is needed: the only package is `Microsoft.NETFramework.ReferenceAssemblies`, which is build-time only.
- Release builds have `DebugType=none`, `Deterministic` and a `PathMap`, so the exe contains no build-machine paths.
- `selftest --keep` keeps the sandboxes for inspection. `selftest --only <name>` runs the tests whose name contains `<name>`.
- `screens --out <dir>` renders every wizard page to PNG, using fake data, for a visual check.
- Building the player setup from a staging folder: see [PAYLOAD_LAYOUT.md](PAYLOAD_LAYOUT.md).

### What the self-test covers

Every end-to-end test packs a fake payload into a real setup exe, runs it with `/silent /target-root=<sandbox>` and checks
the results. Each sandbox is a temp folder (`%TEMP%\ck3xbl setup test\Ünïcødé Тест ...`, so every path has spaces and
non-ASCII letters) that holds:

- fake CK3 and Bannerlord installs;
- a fake Documents folder with a `dlc_load.json`;
- fake AppData and Desktop folders;
- a registry stand-in under `HKCU\Software\CK3xBL-Sandbox\<id>`.

Everything is removed afterwards. No real game folder, Documents folder or real registry entry is touched, and no game or
bridge is started.

| Test | Checks |
|---|---|
| `fresh_install` | every file at its place with the right hash; `ck3xbl.mod` (absolute `path=` with `/`, no BOM, non-ASCII intact); `dlc_load.json` edited and backed up; config seeded; Start menu shortcut; Add/Remove Programs entry; uninstaller copy has no payload |
| `dry_run` | `/dry-run` prints the plan and changes nothing (sandbox snapshot identical, no registry key) |
| `repair_same_version` | re-running repairs a deleted file, adds no duplicate `dlc_load.json` entry, keeps the backup |
| `upgrade` | 0.9.0 to 0.9.1: dropped files removed, a dropped file the player edited kept, shortcuts follow the new choices; downgrade refused without `/allow-downgrade` |
| `junction_refusal` | `Modules\CK3Bridge` as a junction (the dev setup): nothing written or deleted through it, by install or uninstall; `/remove-module-link` removes only the link |
| `foreign_mod` | a `ck3xbl.mod` pointing elsewhere is kept, or with `/replace-existing` moved to a backup and put back by uninstall |
| `invalid_dlc_load` | a broken `dlc_load.json` is never overwritten |
| `uninstall_restores` | uninstall returns the sandbox to its exact earlier state, apart from the kept settings |
| `uninstall_after_launcher_edit` | if the launcher rewrote `dlc_load.json` since, only our entry is removed |
| `uninstall_installed_copy` | `CK3xBL-Uninstall.exe` hands over to a temp copy, removes the install folder including itself, and the temp copy deletes itself |
| `uninstall_delete_user_data` | logs and settings are kept unless `/delete-user-data` is given |
| `foreign_app_files` | files in the install folder that setup did not install are moved to `setup-backups`, not overwritten, and put back by uninstall |
| `install_dir_link` | an install folder that is a junction: setup stops before writing anything |
| `upgrade_step_failure` | a file locked during an upgrade: the step fails, the earlier files stay recorded, uninstall still removes everything |
| `uninstall_step_failure` | `dlc_load.json` locked during uninstall: the record, the uninstaller and the Add/Remove Programs entry stay, and a second run finishes |
| `uninstall_keeps_unrestored_backup` | a replaced foreign module whose place is now taken by files the player changed: `/delete-user-data` deletes the settings and logs but keeps `setup-backups` |
| `uninstall_incomplete_keeps_moved_aside` | uninstall while Bannerlord runs keeps the moved-aside record; the next run puts the player's module back |
| `uninstall_run_key` | the bridge's "Start with Windows" entry is removed when it starts this install, and left alone when it starts another copy |
| `documents_moved` | the Documents folder moved since the last install: the upgrade follows it (mod, mod list record, bridge settings); a folder the player chose is kept |
| `elevated_helper_checks` | the elevated helper refuses requests with paths outside its folders, and puts a moved-aside module back |
| `modules_not_writable` | deny-ACL on `Modules`: the module step fails cleanly, a copy for manual install is put next to the app, other steps succeed |
| `bannerlord_running` | a program running from the Bannerlord folder blocks the module step ("close Bannerlord"), nothing is killed |
| unit tests | JSON round trip, `dlc_load.json` edits (BOM, `\`, absolute entries, invalid input), versions, Steam `libraryfolders.vdf`, payload path rules, leak gate, tampered and signed payloads, sandbox context, process matching by folder, install folder rules, which recorded files may be deleted |

## What setup does

**Wizard:** Welcome, License (MIT plus the not-affiliated notice), Game folders, Options, Installing, Finished.

**Game folders.** Setup detects CK3 and Bannerlord from:

1. Steam (`SteamPath` in the registry, `libraryfolders.vdf`, `appmanifest_<id>.acf`);
2. Steam's uninstall entries;
3. GOG (`HKLM\SOFTWARE\[WOW6432Node\]GOG.com\Games\*\path`);
4. Epic (the launcher's `*.item` manifests).

Each folder has a Browse button. A folder counts only if it holds `binaries\ck3.exe` or
`bin\Win64_Shipping_Client\Bannerlord.exe`. The page shows the game versions and warns on versions this release was not
built for (CK3 1.20.x, Bannerlord v1.4.x) and on GOG and Epic, which are untested. It never blocks.

**Install folder.** A folder that already holds other files, or a drive root, gets its own `CK3xBL` folder inside it,
whether it is picked with Browse, typed, or given with `/install-dir`. An install folder that is a junction or symbolic
link is refused.

**Options (defaults):**

| Option | Default |
|---|---|
| Install the CK3 mod | on |
| Add the mod to CK3's current mod list (`dlc_load.json`, backup kept) | on |
| Install the Bannerlord module | on |
| Start menu shortcut | on |
| Desktop shortcut | off |
| Start Crowns & Blades now | on (Finished page) |

**Where things go:**

| What | Where |
|---|---|
| App | `%LOCALAPPDATA%\Programs\CK3xBL\` (`CK3xBL.exe`, `data\`, licences, `CK3xBL-Uninstall.exe`, `install_manifest.json`) |
| CK3 mod | `<Documents>\Paradox Interactive\Crusader Kings III\mod\ck3xbl\` plus `mod\ck3xbl.mod`; `<Documents>` is the real Documents folder (`SpecialFolder.MyDocuments`, OneDrive-redirected or not) |
| Mod list | `dlc_load.json` gets one entry, `mod/ck3xbl.mod`; the original is kept once as `dlc_load.json.ck3xbl_backup`, and an existing backup that is not ours is never touched |
| Bannerlord module | `<Bannerlord>\Modules\CK3Bridge\` |
| Settings | `%LOCALAPPDATA%\ck3xbl\config.json` is seeded with the chosen game folders, only when absent |
| Uninstall entry | `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\CK3xBL` |
| Shortcuts | Start menu (and the Desktop if ticked): `Crowns & Blades.lnk` |
| Setup log | `%LOCALAPPDATA%\ck3xbl\setup.log`; uninstall: `%TEMP%\CK3xBL-Uninstall.log` |

Nothing is written into the CK3 install, Bannerlord's own files, `launcher-v2.sqlite` or the Bannerlord settings in
Documents.

**Safety rules:**

- **Links are never written through.** If `Modules\CK3Bridge` (or the mod folder) is a junction or symbolic link, as in the
  developer setup, setup says where it points and offers to remove **the link only**, never its target. Silent mode
  leaves it unless `/remove-module-link` is given. A link at or inside the install folder is never written through
  either. Uninstall never deletes through a link.
- **Foreign copies are moved, not overwritten.** A `ck3xbl.mod`, `mod\ck3xbl\` or `Modules\CK3Bridge\` that this setup did
  not install is replaced only after the player confirms (or with `/replace-existing`). A file in the install folder that
  setup did not install is moved without asking. The old copies go to `%LOCALAPPDATA%\ck3xbl\setup-backups\<time>\`, and
  uninstall puts them back.
- **Setup deletes only in its own folders.** Whatever `install_manifest.json` says, a file is deleted only in the install
  folder, a `...\mod\ck3xbl\` folder (plus `mod\ck3xbl.mod`) or a `...\Modules\CK3Bridge\` folder, and only while its
  SHA-256 matches. The elevated helper trusts no path in its request: it works only in `Modules\CK3Bridge` and the
  player's `setup-backups` folder.
- **For your own Windows user.** If setup runs as another account (an administrator's password typed into the UAC
  prompt), it stops and says so. Started with "Run as administrator" on the player's own account, it warns first. If the
  player continues, it never starts the bridge, so Bannerlord is never started elevated.
- **Running programs are never killed.**
  - A running `CK3xBL.exe` from the install folder is asked to quit through its quit event. If the bridge is too old to
    have one, the player is asked to quit it from the tray.
  - A running Bannerlord blocks only the module step ("close Bannerlord, then Retry").
  - A running CK3 only postpones the `dlc_load.json` edit.
- **No administrator rights by default.** If `Modules` is not writable (some GOG, Epic or Program Files installs), the wizard
  asks and re-launches setup elevated (`runas`) for the module step only. If the player declines, or in silent mode, the
  module is placed in `<install>\bannerlord-module\CK3Bridge` and the Finished page says where to copy it.
- **The payload is verified before anything is written:** sizes and SHA-256 of every file, no unlisted entries, safe paths.

**Upgrade and repair.** Running a newer setup over an install replaces the files and removes files that the new version
no longer has, but only when they are unchanged since install. The same version repairs. An older version asks first
(`/allow-downgrade` in silent mode). The folders chosen last time are kept. The CK3 user folder is the exception: if
Windows or OneDrive moved the Documents folder since the last install, it follows the new place, and the mod, the mod
list record and the CK3 folder in the bridge settings move with it. A CK3 user folder the player chose by hand is kept.

If a step fails part-way (a locked file, a full disk), the earlier install's records for that step are kept, so
uninstall still removes those files. The uninstaller is written first, and the Add/Remove Programs entry is made only
when it is on disk. Right after install, setup checks that `CK3xBL.exe` is still there. If an antivirus quarantined it,
the Finished page says so instead of reporting success.

**Uninstall** works from Add/Remove Programs, from `CK3xBL-Setup.exe /uninstall`, or by running
`<install>\CK3xBL-Uninstall.exe`. It removes exactly what `install_manifest.json` lists:

- **Files** are deleted only while their SHA-256 still matches. A changed file is the player's now, so it is kept and logged.
- **`dlc_load.json`:** if it is unchanged since setup wrote it, the backup is restored byte for byte. If the launcher or
  the player changed it since, only our entry is removed and everything else stays.
- **Moved-aside copies** are put back when their place is free. Putting a module back into a `Modules` folder that needs
  administrator rights asks for them. If files the player changed now occupy the place, the copy stays in
  `setup-backups` and the result says where.
- **Settings, logs and the battle archive** in `%LOCALAPPDATA%\ck3xbl` are kept unless "Also delete my Crowns & Blades
  settings, logs and battle archive" is ticked (or `/delete-user-data` is given). `setup-backups` is never deleted while
  it holds the player's own earlier copies. Saves are never touched.
- **The bridge's "Start with Windows" entry** (`HKCU\...\Run\CK3xBL`) is removed when it starts this install's
  `CK3xBL.exe`. An entry that starts another copy, such as a source checkout, is left alone.
- **When something cannot be removed yet** (Bannerlord running, no rights, a locked file, a step that failed), the rest
  is still removed. The uninstaller, a reduced manifest (which includes the copies not yet put back) and the Add/Remove
  Programs entry stay, so uninstall can be run again.

## Command line

```
CK3xBL-Setup.exe [options]
  (no options)          the setup wizard
  /uninstall            remove Crowns & Blades
  /silent               no windows (exit codes below)
  /dry-run              print the plan, change nothing (works with and without /silent)
  /target-root=<dir>    sandbox: every destination (install folder, Documents, AppData, Desktop, Temp, both game folders
                        <dir>\Games\..., registry under HKCU\Software\CK3xBL-Sandbox\<id>) is under <dir>
  /install-dir= /ck3-dir= /ck3-user-dir= /bl-dir=     single overrides
  /payload=<file>       use this payload (.zip or a packed setup .exe) instead of the one inside the exe
  /log=<file>           log file          /result=<file>   writes {"exitCode":n} when done (for scripts)
  /no-ck3-mod /no-dlc-load /no-bl-module /no-start-menu /desktop-shortcut /start-bridge
  /replace-existing     /remove-module-link     /allow-downgrade     /delete-user-data (with /uninstall)
```

- **Any** target override switches game auto-detection off, so a test can never fall through to a real install.
- In sandbox mode, setup never starts the bridge, never asks for administrator rights and never signals a real bridge.

| Exit code | Meaning |
|---|---|
| 0 | done |
| 1 | done, but a step was skipped, failed or needs attention (see the log) |
| 2 | failed (damaged payload, refused downgrade, nothing installed) |
| 3 | blocked: Crowns & Blades is running and was not closed |
| 4 | bad arguments |
| 5 | cancelled |

`CK3xBL-Setup.exe` is a Windows (GUI) program. When it is started from a terminal with `/silent` or `/dry-run`, it attaches
to that terminal to print. Scripts should wait for it (`Start-Process -Wait`) and read the exit code, or pass
`/result=<file>`.

## Contract with the bridge

- **`data\` next to `CK3xBL.exe`:** the bridge finds its tables through `data\ck3_maa_index.json`.
- **Quit event `Local\CK3xBL.Bridge.Quit`** (also `CK3xBL.exe --quit`): setup and uninstall set it to ask a running bridge
  to quit gracefully, then wait up to 30 s. A bridge that does not quit is left running, and the player is asked to quit
  it from the tray.
- **Single-instance mutex `Local\CK3xBL.Bridge.SingleInstance`:** setup checks it before "Start Crowns & Blades now", so it
  never starts a second copy.
- **Settings in `%LOCALAPPDATA%\ck3xbl\config.json`:** setup seeds them there, and an installed bridge reads that file. A
  source checkout keeps `bridge\config.json`.
- **"Start with Windows":** the bridge writes `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `CK3xBL`, as
  `"<path of CK3xBL.exe>"`. Uninstall removes it when that path is in the install folder.

## Known limitations (0.9.0-beta)

- **The elevated module step (UAC) is not covered end to end by the self-test,** because the self-test cannot accept a
  UAC prompt. The helper's request checks and its restore step are tested by running the helper unelevated, and its
  install and uninstall steps are the same `ModuleInstaller` code the tests run. The "Run as administrator" and
  other-account checks are not covered either.
- **The exe is unsigned:** expect a SmartScreen "Windows protected your PC" prompt (More info, then Run anyway). Signing
  after packing is supported (section 3 of PAYLOAD_LAYOUT.md).
- **Not supported:** Xbox / Game Pass. **Untested:** GOG and Epic detection, and an Epic Bannerlord started directly.
- **The Paradox Launcher rewrites `dlc_load.json`** from the selected playset every time Play is pressed there. Players must
  add "Crowns & Blades Battles" to their playset; the Finished page says so.
- **Untested in CK3:** a CK3 `path=` under a Windows user name with non-ASCII letters. The installer side writes and
  verifies it.
